# Подключение Google Таблицы

Интеграция использует привязанный к таблице Google Apps Script как небольшой API. Публичное табло читает состояние из таблицы, а запись из админки требует отдельный ключ. По умолчанию ключ хранится в `sessionStorage`; если включить **Запомнить доступ на этом компьютере**, он также сохраняется в `localStorage` этого браузера, чтобы не проверять запись заново после перезапуска. Не включайте эту опцию на общем компьютере и не добавляйте ключ в Git или переменные сборки.

## Настройка таблицы и Apps Script

Новая таблица уже создана: [Friendly Poker — хранилище сезона 1](https://docs.google.com/spreadsheets/d/1dFlXbRu1G1Fk9xl_Y4zzidWucesVoAbcJxMNBU_z-dk/edit). Откройте её в аккаунте Google, который будет владельцем турниров, затем:

1. Выберите **Расширения → Apps Script**.
2. Замените содержимое `Code.gs` кодом из этого каталога и сохраните проект.
3. Для новой пустой таблицы выберите `setupPokerDatabase` и нажмите **Выполнить**. При первом запуске Google попросит разрешить скрипту доступ к таблице.
4. Для уже подключённой таблицы запустите `migrateToReadableSheets`. Это перенесёт прежний JSON-снимок в отдельные читаемые вкладки и сохранит действующий ключ администратора.
5. При первоначальной настройке откройте журнал выполнения и скопируйте строку `Friendly Poker admin key`. Сохраните ключ приватно; позже вставьте его в панель управления приложения. `setupPokerDatabase` нужен только для первой настройки: повторный запуск сообщит, что база уже настроена, и оставит ключ и данные без изменений. Для публикации обновлений используйте **Развернуть → Управление развертываниями → Изменить → Новая версия**.
6. Откройте **Развернуть → Управление развертываниями**, нажмите карандаш у текущего веб-приложения, выберите **Новая версия** и сохраните. URL `/exec`, права доступа и действующий ключ останутся прежними.

Доступ **все** делает чтение турниров публичным: экрану не нужен вход в Google. Любой человек со ссылкой на скрипт сможет прочитать состояние турнира; поэтому не храните там закрытые или персональные данные. Изменение таблицы требует отдельный случайный ключ администратора, который не включается в публичный сайт.

После миграции пользователь увидит вкладку `Участники` со списком имён, отдельную вкладку для каждого турнира и общий `Журнал действий`. В турнирной вкладке настройки оформлены парами `Параметр / Значение`, рядом находятся состав, уровни блайндов, автоматические места и докупки, текущие стеки и журнал раздач. Для каждой улицы в журнале сохраняются отдельные действия игрока и сумма внесённых фишек. Блайнды помечаются автоматически; по сумме относительно предыдущей ставки приложение определяет колл, ставку или рейз, а чек фиксируется кнопкой в ячейке. Вкладка `Журнал действий` показывает каждое записанное действие отдельной строкой и подходит для фильтрации по турниру, раздаче, игроку и типу. Улица, на которой игрок сбросил карты, записывается отдельно: на этой улице он остаётся виден, а на следующих скрывается. Технические ID хранятся в скрытых ячейках. Админка сама рассчитывает стек, банк, баланс и места по истории ставок и подтверждённым вылетам; если несколько игроков подтверждены выбывшими в одной раздаче, им назначается одно место и одно количество очков, а следующее место пропускается. Таблица остаётся читаемым журналом.

Перед стартом расставьте выбранных игроков в порядке по часовой стрелке и выберите первого дилера. Малый и большой блайнды определятся по этому порядку. В каждой следующей раздаче дилер перемещается к следующему оставшемуся игроку; при двух игроках дилер совмещает малый блайнд. Роли сохраняются вместе с каждой раздачей в колонке «Роли». Для уже начатого турнира без сохранённых ролей можно выбрать дилера перед первой раздачей с новым учётом.

Техническая вкладка `_PokerData` скрыта: в ней остаются номер версии данных, список активных турниров и резервная копия прежнего JSON-снимка. Новые турниры создают собственные вкладки автоматически. Для изменения состава, имени, настроек и результатов используйте админ-панель; таблица служит для чтения и проверки данных. Публичный URL отдаёт данные для экрана, поэтому не добавляйте в турнирную модель закрытые или персональные данные.

## Локальный запуск

Создайте `.env.local` в корне проекта:

```dotenv
VITE_GOOGLE_APPS_SCRIPT_URL=https://script.google.com/macros/s/ВАШ_DEPLOYMENT_ID/exec
```

Затем перезапустите `npm run dev`, откройте `/admin`, вставьте admin key и нажмите **Включить запись**. Если таблица пустая, приложение запишет в неё текущее демо-состояние.

## GitHub Pages

В репозитории GitHub откройте **Settings → Secrets and variables → Actions → Variables** и добавьте переменную `VITE_GOOGLE_APPS_SCRIPT_URL` со значением URL `/exec`. URL не является секретом. Workflow использует эту переменную при сборке страницы; admin key в GitHub добавлять не нужно.

При первом нажатии **Начать турнир** приложение фиксирует фактическое время старта, запускает таймер и выдаёт одинаковый стартовый стек составу. При начале каждой раздачи малый и большой блайнды автоматически записываются в первые взносы игроков, назначенных на эти роли. Во время раздачи выберите улицу, внесите каждый отдельный взнос игрока в свой столбец и переключитесь дальше кнопкой **Следующая улица**. Для нулевого действия нажмите **Чек**. Ненулевые действия получают подпись колла, ставки или рейза по предыдущим взносам на этой улице. Банк и остаток стека пересчитываются автоматически по сумме взносов. После закрытия раздачи денежный баланс пересчитывается; отмеченные победители делят банк поровну. Разделение побочных банков при олл-инах пока не реализовано, поэтому эта версия рассчитана на учёт одного общего банка. Докупка ограничивается числом и временем из настроек турнира, а вылет подтверждается отдельно после окончания раздачи. Если одновременно выбыли два игрока из четырёх оставшихся, оба получают 4-е место и очки за него; 3-е место пропускается. Время показывается в часовом поясе `Asia/Krasnoyarsk`; пауза и продолжение не меняют первоначальное время старта. Клиенты перечитывают таблицу раз в 30 секунд, а каждый экран считает таймер от сохранённой временной отметки, поэтому таблица не записывается каждую секунду. Для синхронизации этой версии нужен `Code.gs` с API версии 5: вставьте обновлённый файл в Apps Script и разверните как новую версию. Первая версия рассчитана на одного администратора; не редактируйте один турнир одновременно из нескольких админских вкладок.
