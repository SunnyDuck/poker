# Friendly Poker — чек-лист ревью

Используйте этот список перед публикацией изменений на GitHub Pages. В ревью фиксируйте только подтверждённые проблемы; у каждого замечания указывайте серьёзность, файл и строку, сценарий воспроизведения и ожидаемое поведение.

## Автоматические проверки

Требуется Node.js 22.18 или новее.

```sh
npm ci
npm test
npm run build
```

Сборка должна завершиться без ошибок, тесты — пройти. Для GitHub Pages проверьте, что Vite собирает сайт с базовым путём `/<имя-репозитория>/`.

## Функциональные проверки

- Главная страница показывает расписание, рейтинг выше статистики, статистику всех игроков и результаты турниров.
- Администратор может менять состав, имена участников и стартовые роли до начала турнира; после старта заблокированные настройки нельзя изменить.
- На табло игроки расположены вокруг стола; видны роли, текущие ставки, блайнды, таймер и следующий уровень. Проверьте экран 1280×720 с 10 игроками: нет прокрутки и карточки мест не перекрывают друг друга.
- В журнале раздачи переключаются улицы; ставки и действия сохраняются по столбцам, нулевое действие фиксируется как чек, колл и рейз определяются по суммам.
- Проверьте малый и большой блайнды, олл-ин, фолд, распределение банка, стеков и одновременный вылет игроков.
- После перезагрузки данные остаются на месте. Проверьте чтение и запись через Google Sheets, миграцию читаемых вкладок, историю раздач и поведение при конфликте или задержке записи.
- Прямые ссылки на `/#/admin`, `/#/admin/tournaments/<id>` и `/#/screen/<id>` открываются после публикации на GitHub Pages.

## Безопасность и публикация

- В коммит не попали `.env`-файлы, ключ администратора, приватные токены и временные снимки браузера.
- URL Apps Script задаётся переменной GitHub Actions `VITE_GOOGLE_APPS_SCRIPT_URL`; ключ администратора остаётся в браузере администратора и не включается в сборку.
- В Apps Script развёрнута совместимая версия API; публикация фронтенда на GitHub Pages сама по себе не обновляет Apps Script.

## Формат результата ревью

Сначала перечислите блокирующие замечания по серьёзности с точными ссылками на строки. Затем укажите непроверенные сценарии и результаты автоматических проверок. Если проблем не найдено, явно укажите проверенные области и оставшиеся ограничения.
